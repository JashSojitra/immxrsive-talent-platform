# Student repository intake and demonstration guide

Permissions and agreements are handled by the administrator outside this website. This guide introduces no website student approval, invitation, verification or consent gate. Existing student-owned workflows remain separate.

1. Receive the original public repository and operational permission record outside the platform. Keep private records outside public descriptions. Open `/admin/projects/new` and paste the exact `https://github.com/owner/repository` page URL. A student never needs to sign in or connect GitHub.
2. Fetch suggestions. Review name, description, languages, homepage and updated metadata. Languages are evidence for technologies; frameworks/authorship/institutional verification are not inferred. Apply suggestions explicitly to empty fields, then edit them. Later fetches do not overwrite existing edits. Imports use fixed GitHub API endpoints, no credentials, no redirect following, a shared 5-second deadline and 128 KiB per response. Private/404, rate-limited, timed-out and unavailable repositories leave manual entry available.
3. Review exact repository and similar-title warnings. `Check project matches` also works for manual entry. Exact admin repository duplicates are rejected on save under advisory locks and a unique index, including archived records; reuse the existing admin record. Public student/legacy matches are warnings and never merged, converted or seized. Private student identities/titles are not returned. Independently adapted copies can retain the original source reference plus their own adapted repository URL.
4. Complete title, summary, narrative, domain, progress, dates, technologies/tools, attribution, thumbnail and described gallery. Add credits with names, roles and contribution descriptions. Credits need no account. Optional explicitly configured profile IDs must identify legitimate currently public, verified profiles; do not infer them from repository usernames. Links automatically disappear when profiles become private, while descriptive credit and administrator publication remain independent.
5. Adapt and host the demonstration outside ImmXrsive. Keep an independent copy and identity; retain original source attribution and relevant licenses. Review hosted content and public URLs manually. Importing never downloads/builds/executes repository code or deploys to the application server. Do not use its production secrets, session cookies or deployment account to build untrusted student code.

| Mode | Configuration | Operator verification |
| --- | --- | --- |
| Safe web embed | Public HTTPS URL on an independent origin, fallback narrative and optional media | Launch the opaque `sandbox=allow-scripts` frame; test keyboard, close, fullscreen where supported and external fallback. No forms, popups, same-origin privilege, camera, microphone, geolocation, payments, USB or XR device permission are granted. |
| Hosted external | Independently hosted HTTPS experience URL | Test the explicit external link, source attribution and return navigation. This supports hosts/frameworks that cannot run within the restricted sandbox. |
| Video walkthrough | Direct MP4/WebM/OGV URL, or supported public video-host HTTPS link, plus description/transcript | Direct media renders with accessible controls and no autoplay; other hosts launch externally. No arbitrary video-provider iframe HTML or script is accepted. |
| Static showcase | Narrative, technologies, thumbnail/gallery, source and fallback | Test missing-image descriptions, readable credits and source links. |
| XR/native | Device/platform details and installation/source instructions; optional external launch, video/screenshots | Confirm the actual supported device/build. The page explicitly says native applications do not automatically run in a browser. |

React, Next.js, vanilla JavaScript and Three.js may supply compatible hosted web builds. Unity needs a separately prepared compatible WebGL build for web use; native/XR packages may need installation on specific hardware. WebXR/device permissions are intentionally not granted within this sandbox; use a reviewed external host for device access. An automatic build/deployment pipeline would require a separately isolated trusted design and is not included.

No source edit is required to attach another hosted experience. URLs are structured fields, never iframe HTML. Validation rejects non-HTTPS URLs, credentials, local/numeric hosts and known wildcard IP resolver domains; arbitrary demo/media URLs are never fetched by the server or image optimizer. This is syntactic URL validation, not a DNS, malware, license or uptime certification. Review the actual host operationally. The iframe rejects the application's own origin at launch; keep adapted apps on a distinct origin.

Embeds start only on explicit launch. A cross-origin `load` event does not prove a working experience: framing headers, sandbox restrictions, network errors or device incompatibility may still show a blank page. After 10 seconds the player advises external launch/fallback; alternate narrative and media remain outside the frame throughout. Use the external link on mobile or unsupported hardware. A missing image/video retains descriptive text and alternate links. Fullscreen depends on browser support and policy and may be denied.

6. Save as a private draft, then open saved preview. Check desktop, 390px width, reduced motion, keyboard focus/labels, gallery alternatives and the actual hosted demo. Preview never publishes, and publication never waits for a student. The technical review page is an operator worklist, not an approval queue.
7. Publish directly. `/projects/[id]`, its public API and `/showcase` expose the new presentation immediately following the successful transaction. Admin provenance, staff identities, audit snapshots and credit profile IDs are excluded from the public projection. Descriptive credits never generate personal skills or talent membership.
8. Test public discovery/search in `/showcase` and project inquiries. Published edits are immediate. Unpublish/archive hides public content and inquiries; restore returns a private draft. Stable IDs and saved event snapshots remain.
